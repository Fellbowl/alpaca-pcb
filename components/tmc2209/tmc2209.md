# tmc2209.c - Driver Motor TMC2209

## Descripción General
Driver completo para motor paso a paso TMC2209 con comunicación UART.

Características:
- Comunicación UART con protocolo proprietary de Trinamic
- CRC8 para integridad de datagramas
- Control de corriente de holding y running
- Microsteps seleccionable (1/256 típico)
- Lectura de estado y posición de pasos
- Generación de pulsos de paso (STEP) por GPIO

## Protocolo UART Trinamic

### Estructura de Datagramas

**Lectura (4 bytes + respuesta):**
```
[0x05] [ADDR] [REG] [CRC8]
```

**Escritura (8 bytes):**
```
[0x05] [ADDR] [REG|0x80] [VAL_B3] [VAL_B2] [VAL_B1] [VAL_B0] [CRC8]
```

### Parámetros
- **0x05**: Sync byte (fijo)
- **ADDR**: Dirección del driver (típicamente 0)
- **REG**: Dirección de registro
- **VAL_Bn**: Valor de 32 bits big-endian
- **CRC8**: Checksum polynomial 0x07

### Echo y Validación
- Después de escritura: TMC2209 devuelve echo de datagram
- Echo incompleto: Posible ruido (log warning, no error)
- Verificación real: Leer registro tras escritura

## CRC8

### Función `tmc_crc8(const uint8_t *datagram, uint8_t len)`
Calcula CRC8 para validación de datagramas.

**Algoritmo:**
- Polynomial: 0x07
- Itera bit a bit sobre cada byte
- Retorna CRC calculado

**Precisión:** Detecta inversiones de bits y mutaciones


## Rampa de Velocidad (Aceleración)

Perfil de velocidad preconfigurado en main.c:

```c
#define TARGET_REV_PER_SEC_START   0.05        /* ~10 RPM en arranque */
#define TARGET_REV_PER_SEC_CRUISE  0.30        /* ~18 RPM en crucero */
```

**Cálculo de semi-período durante init:**
```c
steps_per_rev = 200 × 256 = 51,200 micropasos/revolución
half_period_start_us  = 1,000,000 / (2 × 0.05 × 51,200)  ≈ 190 us
half_period_cruise_us = 1,000,000 / (2 × 0.30 × 51,200)  ≈ 32 us
```

El generador de pasos respeta estos timings mediante `esp_rom_delay_us()` entre pulsos STEP.

## Registros Principales

### Configuración
- **REG_GCONF (0x00)**: General configuration
- **REG_CHOPCONF (0x6C)**: Chopper configuration
  - MRES: Microstep resolution
- **REG_IHOLD_IRUN (0x10)**: Corrientes
  - IHOLD: Corriente de holding
  - IRUN: Corriente de running

### Estado
- **REG_GSTAT (0x01)**: General status
- **REG_IFCNT (0x02)**: Interface counter (echo OK)
- **REG_DRV_STATUS (0x6F)**: Driver status
- **REG_MSCNT (0x6A)**: Posición actual de microstep

## Funciones de Bajo Nivel

### `tmc_write(tmc2209_t *drv, uint8_t reg, uint32_t value)`
Escribe registro sin retornar error.

**Procedimiento:**
1. Arma datagrama de 8 bytes
2. Calcula CRC8
3. Flush de buffer UART
4. Envía datagram
5. Espera transmisión
6. Lee echo (no valida)
7. Log warning si echo incompleto

**Rationale:** Echo incompleto no prueba fallos (puede ser ruido)

### `tmc_read(tmc2209_t *drv, uint8_t reg, uint32_t *out_value)`
Lee registro con validación de CRC.

**Retorna:**
- `ESP_OK`: Lectura exitosa
- `ESP_ERR_TIMEOUT`: Sin respuesta
- `ESP_ERR_INVALID_CRC`: Respuesta corrupta

## Generación de Pasos

### `tmc2209_move_steps(tmc2209_t *drv, int32_t steps, bool dir_close)`
Genera pulsos de STEP para mover motor.

**Parámetros:**
- `steps`: Cantidad de micropasos (positivo)
- `dir_close`: true = cierra focuser (dir=1), false = abre (dir=0)

**Procedimiento:**
1. Establece pin DIR según dirección
2. Para cada paso:
   - Pulso STEP: HIGH → LOW (con delay para cumplir timing)
   - Cada 500 pasos: `vTaskYield()` (evita watchdog)
   - Avanza microsegundos con `esp_rom_delay_us()`
3. Retorna total de pasos ejecutados

**Timing:**
- Respetar datasheet TMC2209 (pulse width/spacing)
- Iteración suave: yield cada 500 pasos para FreeRTOS

**Constantes:**
- `MICROSTEPS_FULL_1_256`: 256 micropasos por paso completo
- `FULL_STEPS_PER_REV`: 200 pasos completos por revolución
- `YIELD_EVERY_N_STEPS`: 500 pasos antes de ceder CPU

## Integración de Sistema

### En motor_task (Core 1)
```
while (true) {
    xQueueReceive(motor_cmd_queue, &cmd, portMAX_DELAY);
    executed = tmc2209_move_steps(&tmc_drv, cmd.steps, cmd.dir);
    focuser_handler_report_move_done(executed);
}
```

### Sincronización
- Solo motor_task llama `tmc2209_move_steps()`
- Core 1 exclusivo → Sin ISR de WiFi/radio
- Garantía de timing para step generation

## Configuración Hardware

### Pines de Control
- **STEP (GPIO5)**: Pulsos de paso
- **DIR (GPIO6)**: Dirección (0=abre, 1=cierra)
- **EN (GPIO21)**: Enable (activo en bajo)
- **UART1 (GPIO17/18)**: Comunicación

### Parámetros de Motor
- **Resolución:** 1/256 micropasos (MRES=0)
- **IHOLD/IRUN:** Corrientes configurables
- **Dirección TMC:** PDN_UART line biasing 1k

## Notas de Diseño

1. **CRC8 obligatorio:** Valida integridad en UART
2. **Echo no es error:** Ruido del camino de vuelta no = fallo
3. **Verificación por lectura:** Leer registro tras write es forma segura
4. **Task yield:** Impide que motor task se cuelgue
5. **Privacidad de registros:** Headers exponen operaciones, no registros crudos

## Dependencias

- FreeRTOS: `task.h`, semáforos
- ESP-IDF drivers:
  - `driver/uart.h`: UART1
  - `driver/gpio.h`: STEP/DIR/EN
  - `esp_rom_sys.h`: `esp_rom_delay_us()`
- `esp_log.h`: Logging
- `esp_check.h`: Macros de error

## Errores Potenciales y Mitigación

| Problema | Causa | Mitigación |
|----------|-------|-----------|
| No comunica | UART mal configurado | Verificar pines y baudrate |
| Echo incompleto | Ruido EMI | Log warning, verificar por lectura |
| Pasos desincronizados | ISR de radio | Core 1 exclusivo |
| Microsteps perdidos | Timing STEP insuficiente | Revisar MHz del reloj |
| Motor no se mueve | GPIO EN no activado | Verificar secuencia de init |
